# 实机诊断与端口选择交接

## 已实现

- 顶栏设备状态可打开独立 MIDI 输入/输出选择。默认 BCR2000 Port 1，手动支持通用 USB-MIDI/DIN/网络接口并保存稳定 UniqueID；
  手动端口缺失显示错误，不切换其他设备。离线端点不作为可连接选项。
- 连接身份改变时重新发送当前软件快照，重复相同连接通知不重复回写；NRPN 未完成状态清空。
- 改端口停止学习和已启动的 OSC 输出，保留软件参数和已有实体映射。
- MIDI 服务和输出适配器可注入，测试不需要真实 MIDI 或网络执行端；无效端口文件阻止启动，
  直到用户显式修复，不静默采用另一条路由。
- 新标准库 Python 诊断工具支持 Windows WinMM/macOS CoreMIDI、端口列举、只读监听、
  自动学习一个实际 CC 后五段扫描及尽力恢复。不会询问或假定 Preset 编号，不发送 SysEx/预设写入。
- Mac 提供传统包、MIDI 1 UMP、MIDI 2 下转换、单包重复消息的独立对照和原生虚拟回环。
  原先 App 的 UMP 试验未改善实机结果，已撤回；正式 App 仍使用已验证的传统发送接口。

## 验证

- Swift 157 Core + 45 Console = 202 条通过，包含端口策略、持久化、停止输出、隔离模式、换路由回写测试。
- Python：19 条工作流 + 8 条仿真 + 10 条诊断工具 = 37 条通过。
- App 构建、启动 smoke、命令校验、compileall、workflow help 和净差异检查通过。
- 两版通用 MCP 冒烟及最小窗口端口设置界面检查通过；隔离模式不能启用实体 MIDI。
- 实际选择并确认过输入 Port 1、输出 Port 2/3，之后恢复自动 Port 1。
- 传统包/UMP1/UMP2/UMP2 同包重复 16 次均通过原生虚拟输入与输出校验，未用实体端点作为自检目标。
- 原生 MCP 权限攻击、复位跳过和超大角度预览回归通过。
- Windows 用户实测通过的是此前独立 PowerShell/WinMM 工具；新 Python WinMM 后端只做了离线 ABI/逻辑测试，
  未冒称已获 Windows 原生验收。

## 尚未解决

- Windows 某中间旋钮五段反馈有效；Mac 独立 Python 自动学到中间旋钮并扫描，用户未观察到灯环变化。
- U-1、固件 1.10、断电重连、App 重启、当前用户 CoreMIDI 服务重启、端口 1/2/3、单包重复均未验证回写成功。
- 用户离开后又做了三种原生输出格式×三个端口的有界自动对照，最终只留下最大值 127 请求。
  所有 API 返回成功，但没有用户观察/设备回读，所以结果是“待验收”，不是硬件通过。
- 没有完整重启 Mac，也没有删系统 MIDI 设置、刷固件、回放备份或安装驱动。
  下一步是完整重启后的同脚本对照；USB 主机路径具体根因仍待确定。
