## 交付范围

- 提供独立诊断入口、只读预检、受控实机查询矩阵、显式写入回读、原子私有报告及全程/单 worker 期限。
- legacy/UMP1/UMP2 都有原生虚拟 BCR：身份与碎片化 SysEx 回应、快照、五值写入回读、恢复均自动验证。
- USB 缓存描述通过 GetConfigurationDescriptorPtr 读取，不需要设备打开；不独占、复位、换配置或修改 pipe。
- 可选当前用户 GUI 启动域入口使用随机临时任务，完成和错误路径移除任务，不创建持久登录项或提权。
- 通用工具包带 manifest/文件 SHA-256、ARM/Intel 通用 ad-hoc 读取器，可选 Windows USB 基线和私有已学目标。
  默认不把目标文件转成写入意图，必须显式选择 matrix 与目标；绝不复制 SSH 密钥、环境文件或 Keychain。
- 修复虚拟端点缺少可选 Offline 属性时被误剔除的问题：未知状态明确标注；明确离线或其他属性错误仍不使用。
- Windows 与 Mac 共享只读协议、五值验证和恢复逻辑，避免测试语义分叉。

## 已验证

- 204 条 Swift（157 Core/47 Console）和 65 条 Python（19 工作流/8 仿真/10 MIDI/9 BCR/19 准备设施）通过。
- App build/startup smoke、两版通用 MCP 冒烟、最小窗口端口设置原生检查通过，无新增编译警告。
- USB 读取器 ARM/Intel 都 warnings-as-errors 编译并合并签名；本机架构运行，Intel 仅编译/结构检查，不冒称 Intel 实机通过。
- 直接及 GUI 入口、本机无设备阻止实机写入、GUI 临时任务移除已实际验证。
- 一次虚拟客户端创建 -304 已记录，基础设施只对这一虚拟创建失败显式重试一次；不隐藏失败，不重试实体写入。
- 从打包 ZIP 原生解压后，直接预检、GUI 预检、带私有目标但物理设备缺失的 matrix 都按预期结束。
- 公共逻辑提取后在成功的 Windows 测试机做 SSH 回归，五值再读一致、零输入丢失，最终读回 127，句柄关闭。
- 校验测试包含未知/缺失身份、错误目标、溢出、身份不符、报告不可写、退出清理、恢复、manifest 篡改/路径逃逸、
  私有目标校验、仅 API 成功不能报硬件通过、设备缺失/矩阵过大阻止测试和有界 worker 超时。

命令与阶段日志在忽略的 build/macos-ready-*、build/macos-prep-* 和私有会话目录。
正式分发包在提交后重新构建，manifest 指向干净工作区的确切提交。

## 准备阶段列出的待验项（历史记录）

- Mac 上真正 BCR 的缓存描述读取和 USB pipe/驱动错误，物理查询与 CC 写入回读；目前没有硬件接在此 Mac。
- Mac SSH 与 GUI 执行域是否在目标机器上都能访问设备。本机入口验证不能代替另一台 Mac 的实机结果。
- 灯环视觉验收；设备值回读成功不直接等同光学观察。
- 4-byte Full-Speed Bulk OUT 仍是兼容性线索，不是已经证实或修复的 Apple 根因。
