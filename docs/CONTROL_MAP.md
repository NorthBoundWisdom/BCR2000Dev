# BCR2000 控制器映射与反馈

## 分层模型（2026-11 重构）

```text
物理控件 BCRControlID   ── 固定硬件几何：P(组1–4)×8、推钮按下、B1–B2、E1–E3、U1–U4，共 108 个
   │  HardwareMap        ── 学习得到的 MIDI 身份（kind + channel + number），按设备区分
   ▼
功能分配 ControlAssignment ── 参数 / Agent 主操作 / 复位参数组；按键行为（切换/按住）、反向
   │
   ▼
参数状态 ParameterDefinition + SurfaceEngine ── 软件侧唯一事实来源
```

- 设备输入 → 参数更新 → 写回绑定同一参数的**其他**控件（被转动的编码器本身已显示该位置）。
- 软件修改（滑块、检查器、复位）→ 写回**所有**绑定控件。按键 LED 始终由软件决定。
- 实体绝对模式 180 ms 内与上次反馈同值（NRPN 比较完整 14 位）的输入视为回环并忽略；已知不回显的 Mock 不做此过滤；触发类按键 250 ms 去抖。

### 语言与映射

界面默认跟随系统，也可在顶栏齿轮的设置页选择简体中文或 English，重启后生效。
语言偏好独立保存在应用设置中，不改变已学习 MIDI 身份、控制器简称、参数 ID 或现有配置文件。
参数/分组名称在存储、导出和 MCP 中保留原文；显示时只翻译与中英文内置名称完全相同的文本。
用户自定义名称保持原样；新建参数和载入预置使用当前语言，并保留该配置内复位分组的对应关系。

### 设备源

| 设备源 | 硬件映射 | 虚拟面板操作含义 |
|---|---|---|
| Mock 设备 | Mock 自带预设：通道 1 的 CC 1–108，按面板顺序编号（仅描述 Mock，不代表实体出厂预设） | 模拟实体操作，产生 MIDI 输入，经同一引擎处理 |
| 实体 BCR2000 | 用户学习，保存在 `hardware-map.json` | 软件修改并回写硬件 |

Mock 模式下实体输入只记录在 MIDI 监视器中，不执行。

### 会话与设备边界（WP1）

- `SurfaceSession`（Core，`@MainActor`）持有引擎，执行全部 `SurfaceEffect`，按设备源路由，
  记录最近 300 条 MIDI 事件及未发送反馈数。时钟、映射/配置保存回调和通用动作回调均可注入。
- `SurfaceDevice` 提供主线程输入批次、连接快照与可抛错的 `send`；Mock 适配器包装
  `MockBCR2000`，CoreMIDI 适配器在 App 层管理传输对象，回调只解码后传递值类型。
- 切换设备源保留软件参数，停止学习，换用该设备的映射并整体回写；实体设备无输出端点时
  每条反馈计入丢弃数，不排队。实体双向连接恢复时清零计数并发送当前快照。
- 学习成功后通过注入回调保存实体映射；保存失败保留内存状态并显示错误，不伪装保存成功。
  已学习控件的后续消息不抢占下一个学习目标；不合法的消息类型会发出拒绝通知。
- 会话只发出触碰、学习、连接与失败等语义事件。选中控件、跟随触碰和提示文案留在 App；
  Mock 时间线由共享 `AgentPlugin` 接收注入时间，`BCRMockAgentHost` 在 MainActor 驱动，不依赖窗口刷新。
  生产 GUI/无界面服务注入配置适配器的中性动作/指示绑定，动作和 LED 反馈仍经过同一 Session 管线；
  领域反馈只按 `IndicatorID` 保存。旧 Agent enum/callback 和未注入时 fallback 仅为兼容，见 [兼容边界](SHARED_PLUGINS.md)。
- Agent 按键先执行当前 LED 反馈，再触发 Agent 回调；同步回调写入的新状态保持最后生效，
  按住期间也不会被旧值覆盖，包括运行中→中断。
- CoreMIDI 连接快照与输入批次到达主线程的先后顺序**待 R1 实机验证**，尤其是启动、USB 断开/重连时。
- Mock 的不回显、momentary 按键、组切换和非当前组 LED 记忆等设备行为均**待 R1 实机验证**。
  本次只抽离编排，不改变 Mock 预设编号、消息形状或持久化格式。

### 学习（仅实体模式）

在检查器中选中控件后点“从这里开始学习”，然后操作实体控件：编码器转动、按键按下
（松开不会学习）。学完自动跳到本区下一个未学习控件，可连续扫过整排。已学习控件的后续
消息在学习期间只更新显示，不会被绑定到下一个控件；编码器接受 CC 或显式选择的 14-bit NRPN。

### 全台旋钮批量学习

除逐个 Quick Learn 外，可显式从**实体当前临时预设的完整 BCL 回读**学习全部旋钮，
仍保存到同一个 `hardware-map.json`，不是应用 Mock 预设或推测出厂 CC。
`BCRPresetEncoderLearning` 在 Core 校验连续行号、设备一致性、完整首尾、56 个唯一旋钮定义，
并要求每个身份在同次设备快照中出现；仅接受 0…127 的普通绝对 CC。
重复身份、缺失快照、自定义发送、其他编码或与已有映射冲突时，整批拒绝，保留原配置。
现有参数和功能保持原样；未分配旋钮新增独立 0…127 参数，默认值取回读快照。
此操作不学习旋钮按下或其他按钮，也不发送设备预设写入。

BCL 的编码器 1–32 对应顶部组 1–4，33–56 对应下方三排，编号依据
[B-Control MIDI Implementation §16](https://mountainutilities.eu/system/files/download/BC-MIDI-Implementation-1.2.9.pdf)。
读当前临时预设使用只读 Request Data（0x40，数据 0x7F），等待 `$end`，不能将固定短等待的半份回读当作完整数据。

开发工具（捕获与暂存目录必须保持本地、忽略，不进入 git）：

```bash
python3 tools/read_bcr_preset.py build/encoder-learning
swift run --build-path build/swiftpm BCRProfileTool build/encoder-learning <本机配置目录>
```

第二步只生成经过 Core 校验的 `learned-hardware-map.json`、`learned-surface-configuration.json`，
不会覆盖用户文件。安装前退出 App、备份原文件（记录原配置是否缺省），再将两个暂存文件一起安装到本机配置目录；
重开 App 并选择实体模式。不要在运行中的 App 下修改持久化文件。

通过运行中的 App 验证（先关闭外部执行端输出；token 仅由环境提供）：

```bash
python3 tools/verify_encoder_surface.py --report build/encoder-roundtrip.json
```

该工具要求 56 个独立绝对 CC 参数，五轮不同位置值均经 MCP → SurfaceSession → 引擎效果管线写出，
每轮请求设备快照逐一核对，最后还原并回读初始值；不直接旁路发送旋钮值。
2026-11-11 当前设备已完成 56/56 映射与 280/280 回读，App 反馈丢弃为 0。
此结果验证软件写入与设备值记忆；每个实体旋钮的人工转动、非当前组视觉灯环、按键、Relative/NRPN、
热插拔与长期稳定性仍按 R1 分别验收。

### 步长与触发参数功能（WP5）

参数 step 可缺省；启用后必须为正的有限数值，且能表示该范围。按零点整数倍网格取最近值，
同时允许两端点；等距时取较小值，保证与 7-bit 投影的往返稳定。软件修改、编码器输入、按键动作均吸附。
普通绝对输入仍只镜像其他绑定控件；若吸附后来源位置与设备输入不同，也校正来源控件。

触发参数功能仅允许按键，接受正向按下并沿用 250 ms 去抖；松开不会重复动作，LED 由软件恢复。
所有绑定同一参数的控件（包括这些状态按钮）一起更新：

| 功能 | 按下动作 | LED |
|---|---|---|
| stepParameter | 加正/负步进；越界时停止或直接回到另一端，不保留越界余量 | 当前按下能改变参数时 127，否则 0 |
| setParameter | 设为指定值并按参数规则吸附 | 当前值等于该预设时 127，否则 0 |
| cycleParameter | 按数组顺序循环；当前值不在列表时从第一项开始 | 当前值属于预设列表时 127，否则 0 |

循环列表 1–256 项，必须有限、在范围内，吸附后也不得重复。修改定义会重新校验现有功能。
批量分配按参数数组与面板行的既有顺序绑定；容量不足会在预览中明确列出未分配数量。
确认时校验预览未过期；保留当前参数值、Agent 状态和硬件映射，再回写改变的控件。

### 配置校验与恢复（WP4）

Agent 槽位和 MIDI 身份解码时检查范围；整个功能配置检查版本、名称、参数 ID/范围/默认值、
重复或悬空分配、编码器上的触发功能、Agent 槽位及复位组。硬件映射检查重复控件、重复 MIDI 身份与编码器消息类型。
非法数据不进入引擎。WP4 未改变 JSON 表示；WP5 功能配置 v3；WP7 功能配置与硬件映射均为 v4。

加载失败不改写原文件，按原始字节保存 .invalid.<SHA256>.json 备份，显示持续可关闭提示；
后续保存再次确保原始非法/旧版本数据已备份。备份失败、超过 4 MiB 或写入失败均明确报错且不覆盖原文件。
旧版本读取后仅在内存迁移；用户后续保存时保留原版备份。配置保存失败可重试。

导入/导出使用原生文件面板，分享文件仅含 SurfaceConfiguration。导入先全部校验并确认替换，
先成功保存后再安装到会话；失败不改当前引擎。实体映射保留，参数运行值按新定义默认值恢复。
替换会停止正在进行的学习，并发出可见事件。未编辑的参数草稿自动跟随外部定义；
已编辑草稿保留本地内容，提示采用外部版本或明确保留草稿后再应用。

首次启动使用中性默认配置（general.1…general.8），机械臂示例由“载入预置…”显式选择。
替换配置保留 Agent LED 快照、设备回显过滤与按键去抖策略；已移除分配的控件通过效果管线清零，
实体反馈只使用已学习的 MIDI 身份。每次整体替换均递增会话修订号，运行中的输出在下一周期停止，
即使新旧配置内容相同也不沿用已使能的安全门。

### 外部实际状态（WP6）

软件目标保持唯一写入事实来源。输出安全门对所有来源统一限幅限速；实际遥测只存入独立读数。
安全门/OSC/JSON核心现在来自共享ParameterOutputPlugin，旧Date/地址与本地化留宿主。
心跳间隔超过期限后，即使新心跳早于下一次evaluate到达，也需明确关闭再开启使能，禁止自动恢复；
回退或非有限时间会可见关闭。这不改变实体映射、设备预设或反馈发送边界。
LED 可选目标/实际：实际模式只影响连续参数编码器，按钮和触发 LED 仍由目标语义决定。
外部状态不会触发参数写入或另一轮 OSC 目标。详细协议见 [OSC.md](OSC.md)。

### 编码器精度（WP7，仅 Mock 验收）

厂商手册 §4.3 将 Relative 1 定义为补码、Relative 2 定义为二进制偏移，并列出 14-bit NRPN 模式：
[Behringer 原版手册镜像，第 16 页](https://www.recordcase.de/media/g0/b2/76/1700636180/behringer-bcf2000-user-manual-en.pdf)。
NRPN 的 CC 编号依据 [MIDI Association 控制器表](https://midi.org/midi-1-0-control-change-messages)。
以下设备行为均 **待 R1 实机验证**，不代表用户当前实体预设：

| 模式 | 7-bit 编码 | 14-bit 编码 |
|---|---|---|
| absolute | 0…127 的绝对位置 | 0…16383 的绝对位置 |
| relative1 | 0 中性；1…63 为正；64…127 解释为 -64…-1 | 以 16384 为模的补码，8192 为负半区 |
| relative2 | 64 中性；65…127 为正；0…63 为负 | 8192 为中性，数值减 8192 得有符号幅度 |

相对参数增量 = encoderStep × 有符号幅度；消息幅度保留设备加速度，没有额外猜测时间曲线。
Mock turn(by:) 的 detent 幅度直接编码（单消息对称限在 ±63 / ±8191），软件目标仍按参数吸附/范围校验。
encoderStep 默认 1，可在检查器明确编辑为 0.5、0.25 等；与可选参数 step 吸附是不同概念。
相对输入后回写所有绑定控件的绝对 LED，不能把相对字节本身显示成灯环位置。
相对输入不使用绝对同值回环过滤，以免合法增量被误吞；真实设备是否回显必须在 R1 验证。

NRPN 身份由 kind=nrpn、零基通道 0…15、number 0…16383 构成。
一次完整输出为 CC99 参数 MSB、CC98 参数 LSB、CC6 数值 MSB、CC38 数值 LSB；
组包按通道隔离，跨回调保存选择状态。新 CC99 或 CC98 清除未完成数据，CC100/101 或 CC121 取消选择；
每个数值必须同时收到 CC6 与 CC38，不猜测缺失低位。500 ms 间隔、时钟倒退、设备源/连接/学习切换清空未完成状态。
同通道不同选择器以最后有效选择为准；其他通道独立，普通 CC/Note 保留原路径。
同一个已配置 NRPN 通道不能再将上述保留 CC 绑定成单独控件，冲突时拒绝整个新绑定。

实体学习必须先选择 CC/Note 或 14-bit NRPN；默认仍为 CC/Note，普通 CC99 不会被猜成 NRPN。
NRPN 学习只在完整序列后绑定、保存并自动前进。原始 CC 在监视器中仍可见，输出为一条含完整数值的 NRPN 事件。
Mock 默认预设仍为通道 1 的 CC1–108；检查器可临时把所选编码器改为通道 16、同编号 NRPN，
仅保留本次 Mock 会话，不写实体映射，不改默认预设。切换到实体模式只用实际学习文件。
Mock NRPN 旋转发出真实四 CC 批次，所有模式经 Session/Engine 返回反馈，没有旁路。

配置 v1–v3 缺省 encoderMode=absolute、encoderStep=1；硬件映射 v3 的 CC/Note 身份原样迁移。
硬件映射当前版本 v4，功能配置当前版本 v7（显式外部写保护）（页面选择为会话状态）；加载旧版时显示迁移提示，原始字节在后续保存前备份。
NRPN 目标与实际 LED 投影保留 14 位；UI 灯环仍显示 7-bit 可视化，同时检查器显示完整原始值。

### 审查修正：细调余量

相对输入与 NRPN 软件微调按控件保存吸附前的连续位置，未达到参数 step 的部分跨次累积。
反向操作抵消余量；先夹到参数边界，防止越界持续旋转积压。软件/MCP/绝对输入改变参数、
定义/功能或映射变化会清理相关余量；实际 LED 遥测不改变目标或余量。

实机进度与已观察事实见 [R1 实机验证记录](HARDWARE_VALIDATION.md)。

Codex 进程管理已补基础生命週期回归：未启动及启动失败后的读取返回 EOF，失败后可重试；
标准输入输出、重复启动拒绝、停止释放等待读取与重新启动均有测试。App 默认 Mock，可明确连接 Codex；完整非硬件验收见对应开发文档。

## 页面、宏与反馈调度

设置 → 页面与宏可复制当前功能分配为独立页面。参数定义和值共享；从检查器将切换页面或宏分配给按键。
切回基础页面恢复基础分配。切换保留参数值、清空旧页面待发送反馈，并发送新页面完整 LED 快照；
删除页面/宏会清除相应触发绑定。删除参数同时清理隐藏页面与引用它的宏。
宏支持设置值、步进及 JSON 配置中的分组复位；最多 64 项，不允许递归宏、脚本或页面切换嵌套。
所有参数修改仍通过 SurfaceEngine，并由同一会话效果管线发送反馈。

设置 → 反馈调度可启用每控件最新值合并、全局令牌桶限速、突发上限及错误冷却。
默认关闭；硬件速率需要 HW6 实测校准。掉线、换端点/设备/配置时清空旧队列，重连只投影当前状态。
回环抑制的时间戳以实际发送时间为准。监视器标明已送达、未连接丢弃、发送失败；MIDI 批次保序处理，
界面状态和跟随触碰合并到 16 ms 刷新周期。Mock 始终走即时、确定性的反馈闭环。

### 真实 Codex 审批（P0 修复）

设备触发与 Agent 页点击有独立入口。Codex 的实体/虚拟设备按键在 waitingApproval 时仅显示到 Agent 页阅读后决定的通知，
不改变请求、槽位或 LED；它永不发送 accept。Agent 页点击才打开详情。
批准需要已呈现的具体请求详情及独立按钮确认，令牌绑定本次连接/请求，旧详情不能批准重连后的新请求。
拒绝可直接操作；卡片及详情均提供中断。Mock 演示语义保持不变。
真实审批不自动过期，持续防重放。同一 Turn 的多条审批全部回复后才解除等待；发送成功才提交决定，发送失败可重试。

调度中的实体验证输入会取消该控件旧的待发送值，再应用新的引擎效果；已确认的反馈回环不取消新软件目标。
调度轮询仅在策略开启且队列非空时运行，清空或关闭后立即结束。

## 灯环显示校准（2026-11-12）

删除原先统一的 13 灯累积条算法，使用 15 个灯位。当前设备预设只读回读确认：顶部四组
使用 `12dot`（单点/相邻双点交替），下方三排使用 `1dot`（单点）；模式逐控件学习，不能按位置猜测。
用户在第 4 组前四个旋钮设置的边界，设备快照分别为 2、3、7、12，对应第 1 灯、1+2 灯、
第 2 灯、2+3 灯；最底排左侧单点切换到第 2 灯的最小读数为 5。

单点灯位为 `round(value × 14 / 127)`；单双点交替档为 `round(value × 28 / 127)`，
偶数档显示单灯，奇数档显示相邻两灯。灯位从左下沿顺时针编号，内部为 0…14。
当前两种模式在 0 时均亮第 1 灯，127 时亮第 15 灯。Mock 使用明确声明的同类显示模式，
软件面板与 Mock 共用投影函数，不再按灯的累计数量显示参数值。

硬件映射 v5 保存从当前 BCL 读取的 `ringMode`。v3/v4 只迁移实际学习的 MIDI 身份，不推断显示模式；
模式未知或未校准时面板显示问号。`bar/spread/pan/qual/cut/damp` 尚未做实机校准，不使用近似图案代替。
这些样本验证了当前两类模式的低端边界；其余档位按同一量化公式投影，仍需人工全程对照，不能算作 R1 全量验收。


## GUI 启动读取硬件（2026-11-12）

默认开启跟随时切换软件视图；其后仅按硬件组键不会更新最后输入记录。

当前预设名称可用 `Request Preset Name`（`0x42, 0x7F`）读取。实机回复 `0x21` 的编号为 `0x7F`，
表示当前临时预设，不是面板上的 1…32 编号；不按名称或开机策略猜测当前预设号。

## 对齐设备预设（2026-11-12）

实体模式面板标题中的设备菜单“对齐设备预设…”按软件配置修改设备**当前临时预设**，流程为：
只读读取（`F0 00 20 32 7F 15 40 7F F7`）→ 本机备份到 `Backups/temporary-preset-sha256-*.syx`（相同内容复用；兼容旧时间戳备份）→ 预览 → 用户确认 →
逐行写入并等待 `0x21` 确认 → 回读核对 → 安装新映射并整体回写软件值。不发送 `$store`/`$recall`/`$global`，
断电或重新载入预设即恢复；失败或完成后可发起恢复，写回前仍须通过上下文校验。
备份只保留最近 5 份及最多 5 层恢复点引用的文件，未知/损坏文件和符号链接不清理。

- 补齐按键：未配置、或与旋钮同址的按键分配通道 16 上未被占用的 CC；新身份仅显示按压。
- 按键行为：CC/NOTE 按键统一 `toggleoff`（按下 127、松开 0），开关状态和按键灯由软件决定。
- 灯环：仅顶部 32 个旋钮（下方 24 个硬件只支持点模式）。±对称范围用 `pan`，0 起且有单位的用 `bar`，
  无单位的原始 0…127 保持原模式。`bar`/`pan` 的灯位已于 2026-11-12 实机逐灯核对
  （三组共 24 个值，含 4/5、13/14、49/50、58/59、68/69、122/123 各分界两侧，全部一致）；`bar/off` 未核对。
- `.lock on`：PRESET、STORE/LEARN/EDIT/EXIT 变为普通按键 63–64/53–56，避免设备换预设后与软件不一致。
- 启用按键功能默认关闭；勾选后已确认身份的按键会直接执行分配功能（包括输出使能）。
- 已学习的旋钮/按键身份与设备不一致时拒绝生成方案，不改写已有身份。
- 重写编码器区块会把未分配旋钮的数值恢复为 `.default`；已分配旋钮在完成后由软件整体回写。

### 预设恢复保护（2026-11-13审查修复）

恢复只在原端点路由、实体模式、设备支持读写且未学习时可用。先只读核对当前名称、设备ID和已知预设定义；
普通旋钮值变化不视为换预设。ACK 后还须读回完整备份内容，确认映射落盘，才弹出该恢复层级。
重复对齐保留最多5层恢复历史，旧嵌套记录在加载/保存时展平并裁剪；保留层引用的预设备份受保护。
首条写入ACK后立即持久化正确认行数，再发送下一行；后续逐行进度只更新内存，结束/失败时保存最终行数。
恢复门只需确认行数大于零，避免每行在主线程重写全套恢复历史。部分写入不保证可自动恢复，提示中明确说明。
不可用层可通过设备菜单或失败窗口的“丢弃此恢复层…”二次确认跳过；只弹出当前记录，设备与映射不写入，
预设备份仍保留，较旧层仍必须通过完整内容校验。后续学习发生变化时必须明确确认替换，当前映射另存0600副本；
映射归档最多保留最近5份，旧有效归档在下次归档时修正权限并清理；成功提示包含归档路径。
预设读取取消、行号错误或总时限到达时停止收集，但保持通道独占并排空到`$end`或3秒无数据；
设备断开/路由代际改变则立即终止。名称读取也在取消后收齐33条索引回复或等待3秒无数据，再释放通道。
下一次读写及硬件连接（读取、写软件值、初始化）都须等旧显示读取排空，等待后重新检查取消和路由，不发送重叠请求。
学习/连接切换导致的显示读取中断不发编号失败告警；恢复确认的异步错误只更新所属操作。
旧恢复点缺少校验元数据时只保留备份，不自动推断设备身份或写入。端点UID不是硬件序列号，校验的是可观察路由及预设内容。
