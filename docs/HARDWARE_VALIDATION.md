## 输出方向排查（2026-11-10）

- 本机预设备份中首个编码器的普通绝对 CC 定义和灯环模式，与实际学习身份一致。
  原始映射只保留本机，不在仓库记录；此检查没有发现身份不匹配。
- 当时 App 的手动端点设置把输出指向 `BCR2000 Port 3`，须改回 Port 1。
  但此前默认使用 Port 1 时同样无灯环变化，所以这不是唯一原因。
- 绕过 App 的独立探针向 `BCR2000 Port 1` 按已学习身份发送 CC 扫描（12 次，间隔 0.6 s），
  CoreMIDI 全部返回 0，Port 1 输入没有收到回显；用户观察 P1-1 灯环**无变化**。
  独立工具也复现无显示变化，不能归为 App 独有问题；具体失败层次尚未确定。
- 用户确认固件 1.10、USB 模式 U-1。设备直连 Apple Silicon USB 根端口，Full Speed；
  经 USB hub 连接或更换 Type-C 端口后，灯环仍无变化。

- 后续用户在 Windows 用独立 PowerShell/WinMM 脚本测试 Preset 8 的中间旋钮，确认同一灯环有五段变化。
  这证明设备至少在 Windows 路径上可接受反馈，不应继续判定设备接收功能整体故障。

## G1 跑马灯分场景观察（2026-11-14，ethanmacair，新驱动）

计时用 `tools/time_bcr_transfer.py`：主动模式只发只读请求，listen 模式不发送任何消息、只给设备回复打时间戳；
两种模式都只输出行数与时间，不保存或打印预设内容。写入经 App 的 MCP `apply_preset_alignment`（与对齐窗口同一流程）。
证据类型：**目视** = 用户原话；**计时** = 脚本测得；**推断** = 由前两者推出、未直接证实。

- **计时**：设备回复速率在读取时恒为 36 行/秒、写入确认恒为 16.7 行/秒（约 60 ms/行），逐秒分布无快慢段。
- **计时**：该临时预设逐秒的行类型与平均行长（16.3–16.9 字符）均匀，读取第 2–3 秒（第 72–107 行）是普通编码器段，无特殊内容。
- **推断**：读取顺时针约 3–4 圈/秒（46 圈 → 3.0、3 圈 → 3.5、60 圈 → 3.9）；若每行一步、12 步一圈应为 3.0 圈/秒，与 46 圈吻合，与 60 圈不符。
  写入逆时针约 1 圈/秒；若同样每行一步应为 1.4 圈/秒。“每行一步”既未证实也未推翻。
- **推断**：读取中用户看到的短暂加速，回复速率与内容都无对应变化，可能是 36 步/秒下的视觉频闪错觉，也可能是设备内部与行无关的节奏，未证实。
- 快照与身份查询无动画：跑马灯只伴随 BCL 文本传输。
- 写入后设备临时预设处于对齐状态（18 键按下/松开、`.lock on`），恢复点有效，可用 `restore_preset` 或“恢复原预设”还原。
