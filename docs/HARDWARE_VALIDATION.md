- CoreMIDI 输入：BCR2000 Port 1、Port 2；输出：Port 1、Port 2、Port 3。

  这不是对重开/热插拔可靠性的完整结论。
- 已通过实际转动学到 P1-1，并保存本机硬件映射（v4）；其 MIDI 身份与 Mock 不同。
  不将原始映射或备份内容写入仓库。
- 初始备份阶段 App 保持 Mock；备份完成后已切换实体模式，OSC 输出仍关闭。
- Preset 8 备份已保存：426 个完整 SysEx 帧、11919 字节，行序号连续，末帧包含结束标记；
  文件权限 0600，仅存在本机 Application Support/Backups。未做回放或恢复验证。
- 转动 P1-1 后软件 J1 随输入更新，输入方向已验证。
- 软件写 J1 后 App OUT 值变化，但用户观察硬件灯环没有变化；输出方向未通过。
  未把 CoreMIDI 接受发送等同于设备已显示。U-1、硬件断电重连和 App 重启后仍未通过。

## 输出方向排查（2026-11-10）

- 本机预设备份中首个编码器的普通绝对 CC 定义和灯环模式，与实际学习身份一致。
  原始映射只保留本机，不在仓库记录；此检查没有发现身份不匹配。
- 当时 App 的手动端点设置把输出指向 `BCR2000 Port 3`，须改回 Port 1。
  但此前默认使用 Port 1 时同样无灯环变化，所以这不是唯一原因。
- 绕过 App 的独立探针向 `BCR2000 Port 1` 按已学习身份发送 CC 扫描（12 次，间隔 0.6 s），
  CoreMIDI 全部返回 0，Port 1 输入没有收到回显；用户观察 P1-1 灯环**无变化**。
  独立工具也复现无显示变化，不能归为 App 独有问题；具体失败层次尚未确定。
- 用户确认固件 1.10、USB 模式 U-1。设备直连 Apple Silicon USB 根端口，Full Speed；
  经 USB hub 连接或更换 Type-C 端口后，灯环仍无变化。
- 只读 B-Control 身份查询（`F0 00 20 32 dd mm 01 F7`；dd/mm 取 7F/7F、00/15、7F/15、00/7F）
  分别发往 Port 1/2/3，监听 Port 1/2 输入均**无应答**。监听程序已用虚拟回环验证能收到 CC 与 SysEx
  （第一版监听程序会丢失 SysEx，其“无应答”结果不计入）。
- 后续用户在 Windows 用独立 PowerShell/WinMM 脚本测试 Preset 8 的中间旋钮，确认同一灯环有五段变化。
  这证明设备至少在 Windows 路径上可接受反馈，不应继续判定设备接收功能整体故障。
