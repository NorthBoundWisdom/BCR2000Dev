# Shared controller regression executor (H-10)

The only scenario data is the locked SurfacePlugins `fixtures/controller-regression-v1.json`, SHA-256 `546fbc2a6f1d20f9e116a91558f4dd67891bfaba797b9778e85d975fe4cd3384`. `ControllerRegressionExecutorTests.swift` interprets its 30 scenarios and 78 ordered steps using real host APIs and fake devices. It never invokes another test by name. It changes no product source, control policy, original test or golden fixture.

The default paths are the clean managed dependency under `build/seed/SurfacePlugins`; results go to `build/h/h10/final`. During coordinated development, `BCR_H10_FIXTURE_PATH`, `BCR_H10_SCHEMA_ROOT` and `BCR_H10_REPORT_ROOT` select explicit data/checker/output paths. The exact fixture hash is checked before execution. An absent/mismatched fixture fails the test; it does not skip or learn a new oracle.

```sh
python3 configs/surface_plugins_dependency.py ensure
swift test --build-path build/swiftpm --filter ControllerRegressionExecutorTests
python3 -B build/seed/SurfacePlugins/scripts/validate_controller_regression.py \
  --report build/h/h10/final/controller-regression-results.json
```

The logical `axis` maps to the first top encoder in physical groups 1/2; `button` maps to the first ordinary button. Parameter p1/p2 and action fire1/fire2 come from the common file. The MIDI addresses come from the existing synthetic map, never from the common fixture. Initial map/configuration/files are all temporary. No MIDI startup occurs, no CoreMIDI endpoint is opened, and no actuator is used.

Output effects come from the session's actual sent/failed MonitorEvents and are cross-checkable against the independent fake transport's raw byte/accepted records. A hardware instance that switches to its internal Mock does not thereby send to the physical fake transport: those other-source outputs remain visible in raw evidence but do not enter its physical effects/counts. Simulation outputs are tracked on the separate simulation instance. sent_value is the last actually accepted native wire value, not the requested target. Zero motor/context output is derived from actual effects; BCR's voice output API cannot express a motor or Program Change.

BCR declares absolute input, relative input, physical group context, display styles, preset transactions and hardware restore. It lacks motors/global motor context commands, so T07–T11, T13, T16–T17 and T21 are physical NA. It fixes input/feedback to the same learned MIDI identity, so T03's independent-address feature is NA. T25 still executes journal overflow and only its motor step is NA.

The current result is **17 pass / 3 fail / 10 NA**, plus one NA step in otherwise passing T25:

- **T18:** The neutral scenario asks for a dynamic global display permission shared by local and remote writes. BCR has no equivalent dynamic GUI gate: its hardware output policy is fixed at session composition, while MCP parameterWrite can be changed. The actual local explicit write sends; the actual remote write is refused. This is a gap in the neutral permission expression/wiring, not a new regression or a violation of the published separation between local operator and remote permissions.
- **T27:** External authority refusal is not connected to the GUI value/error path. The actual-feedback API cannot provide this missing behavior; the real subsequent GUI write renders 100 rather than retaining external actual 10 and an error.
- **T30:** The native endpoint type has IDs/names/availability but no provenance. Identical-name virtual and USB endpoints cannot retain the requested provenance through this API. No existing map display eligibility is upgraded.
