# 供应方能力与依赖盘点

基线：`bf73a5f` 加本工作区既有未提交增量。日期：2026-11-11。
本页记录重构前实际范围；最终能力以版本化清单和黑盒验收记录为准。

| 能力 | 已有实现 | 本轮缺口 |
| --- | --- | --- |
| 控件发现、映射、参数和反馈 | SurfaceSession、CoreMIDI、Mock、MCP 参数工具 | 稳定领域接口、来源/代次完整的控件事件 |
| 参数 SSE | 值快照、revision、合并、背压 | 不等于控件原始输入事件；需要独立事件合同 |
| Agent | 独立状态概念、Mock 和具体后端实现 | 与控制台共 target，具体后端与共享 JSON 需要拆离 |
| 机器人 | 可选预览、参数输出安全门、示例接收端 | 尚无关节设备命令、实际推进状态和停止合同 |
| 底盘 | 无独立设备实现 | 参考 Ackermann 模型、控制权、执行状态与故障合同 |
| 无界面接线 | GUI 内 MCP，已有本机管道凭据启动增量 | 独立宿主、公开启动配置和发布入口 |
| 设备诊断 | 内部 Python 原生协议诊断工具 | 发布独立工具或接口，消费方不再依赖源码路径 |

## 当前依赖事实（DM01）

`BCRAgentCore` 同时包含控制台、Agent 状态、具体 Agent 协议/子进程、MCP、OSC、运动输出门与本地化。
`BCRAgentConsole` 同时装配 UI、CoreMIDI、MCP 网络、输出传输和持久化。
共享 JSON 类型定义在具体 Agent 协议文件中；控制台保护逻辑写死机械臂示例 ID；
默认领域会话使用机械臂配置；MCP 工具的领域处理集中在同一服务。

这属于构建边界不足，不能以已有文件划分说明领域已隔离。拆分方案见 [ADR 0001](adr/0001-provider-domain-boundaries.md)。

## 既有增量与消费方依赖（M01/M02 的输入）

本工作区既有增量包括未绑定控件学习、配置写权限关闭、管道凭据启动及其测试；均需按通用合同整理。
既有消费方反馈验收直接导入 `macos_bcr_roundtrip.py`、`bcr_protocol.py`、`midi_feedback_probe.py`，
间接使用 `diagnostic_io.py`。发布诊断能力后需提供替代调用说明，不能把内部源码布局当作接口。
具体消费方映射、工作流、地址和原始联调数据不进入 BCR 发布合同。

首批只发布 ADR 已选的控制台、关节参考模型和 Ackermann 模型。真实机器人/底盘适配、IK、
厂家程序及设备原生协议列为 unsupported，不能静默模拟成功。
