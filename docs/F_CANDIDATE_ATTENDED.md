This is a prepared plan, rehearsed only with a Debug fake device. The user's device-side button repair
is acknowledged; it does not supply fresh preset/edge/LED/chain evidence for this exact candidate.
**F never starts the physical commands below, installs a candidate or changes a preset/map/profile.**

Machine-readable steps and matching Markdown are generated by:

```sh
python3 configs/prepare_f_candidate_attended.py --output build/f/attended
```

The delivery includes `attended/bcr-four-role-candidate.json` and `.md`. Every step has a command,
agent prompt, one user question, automatic criterion and stop-on-failure instruction. Substitute only
owned ready URL/instance/run directory and exact delivery/candidate paths; secrets never substitute into
command strings. The process owner supplies each credential by private anonymous pipe. For example:

```python
# token already resides in the process owner's memory; do not print or persist it.
subprocess.run(probe_command, input=token.encode(), check=True)
```

`probe_command` is the step's `python3 .../diagnostics/f_candidate_probe.py` argument list. The probe only
contacts an already owned provider; it never opens CoreMIDI. Snapshot/edges are read-only. Display steps
require both the host's write/display gates and the probe's explicit attended-display confirmation.
The probe reports transport acceptance separately from the human observation and always leaves
physical_qualification false. Capture the user's single answer separately; never auto-answer a question.
