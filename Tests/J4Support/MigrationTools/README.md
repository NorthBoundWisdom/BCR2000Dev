# Offline migration/research sources (not default CI tests)

The .swift.txt files preserve one-time49ad oracle exporters and the rejected Foundation visitor
research. They are deliberately outside the compiled test target. Their historical executions,
source SHA/argv/RSS and full outputs are preserved under the workspace build/j-main-cont/b/j4-cut/
foundation-probe evidence. Earlier command-before hashes refer to original executed preformat files;
current text is the later formatted research/tool source, not a replacement historical identity.

Do not wire the Foundation/NSNumber visitor or its withdrawn fallback scanner into a replay.
Its ordinary decimal one-ULP red is real. No stringValue repair/general fallback is approved.
The actual Tests hot path is solely J4PayloadCodec -> strict shared decodePayload(raw), then
shared decodeInput(payload:) for envelopes. Neither a second raw gate nor old slow Data parse
runs there. The original Data API is retained by Kit and only small permanent regression fixtures
compare it in default tests.

The archived J4ASTMigrationVerificationTests has a guarded offline migration mode to compare new actual complete
encoded bytes with preserved real49ad outputs, one record at a time and in original order. It is not compiled in default CI. Permanent small scalar/type/UTF8 checks are in J4PayloadCodecTests. Do not export
old results again after upgrading the lock or overwrite the original oracle. Digest fields identify
files/records; they are not the actual byte-equality comparison.
